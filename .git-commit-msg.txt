fix(bff): SSRF via fetchJSON exportado, fugas de API key y path traversal

Auditoria del backend. Cuatro fallos independientes en la capa de server
actions, todos alcanzables por cualquier usuario con sesion.

1. SSRF. lib/actions/finnhub.actions.ts es 'use server', asi que todo export de
   nivel superior se registra como Server Action y es invocable por HTTP. Se
   exportaba `fetchJSON(url)`, que solo comprobaba *quien* llama
   (requireAuthenticatedUser) y nunca *a donde* va: cualquier usuario
   autenticado podia pedir un GET a http://169.254.169.254/latest/meta-data/,
   a http://localhost:8000/openapi.json o a cualquier RFC1918 y recibir el
   cuerpo. Movido a lib/upstream/finnhub.ts, sin 'use server', de modo que la
   URL solo se construye desde codigo del servidor.

2. Fuga de la API key de Finnhub. Los tres throws de fetchJSON interpolaban la
   URL cruda, y todas las llamadas se construyen como
   `...&token=${token}`: el mensaje de error devuelto al navegador
   contenia la key del servidor. Anade redactUrl() y se usa en todos los
   mensajes. Vive en lib/upstream/redact.ts (puro, sin dependencias) porque lo
   necesitan el resto de clientes de upstream.

3. Violacion latente de 'use server'. `export enum DataSource` y
   `export enum NewsSource` vivian en modulos 'use server'. Un enum compila a
   un objeto, y Next valida en
   next/dist/build/webpack/loaders/next-flight-loader/action-validate.js que
   solo se exporten funciones async (E352). No reventaba porque el DCE de
   Turbopack dejaba el enum fuera del manifiesto de actions mientras nadie lo
   importase desde fuera; el primer import externo (un componente cliente
   necesita el valor para el campo `source`) lo convertia en un fallo de
   build. Movidos a lib/types/vendorSources.ts, mismo patron que
   lib/chat/citations.ts.

4. Path traversal en ids de path. `fiscalYear: number` y `runId: number` son
   anotaciones de tipo, no validacion: una Server Action recibe JSON
   arbitrario. researchRequest hace fetch(`${BACKEND_URL}${path}`) y fetch
   normaliza `..` antes de enviar, asi que getTaxReport("../../../openapi")
   pedia /openapi del engine firmado; y como la firma HMAC se calcula sobre el
   path ya normalizado, seguia siendo valida. Anade lib/validation/pathParams.ts
   y lo aplica a los 8 ids interpolados de lib/actions/research-tools.actions.ts
   mas taxes y thesis-jobs.

Ademas, exportJournal devolvia los primeros 300 caracteres del cuerpo de error
del engine al navegador (posible traceback con rutas, SQL y hostnames). Ahora
se registra en servidor y al cliente solo se le da el status. Y `format` se
validaba solo por tipo antes de interpolarse en la query.

Nuevo scripts/server-action-guard.test.ts con guardas de regresion para los tres
puntos (helper con URL exportado, enum en 'use server', url sin redactar en un
throw). Se cablea en package.json junto a los dos guards de identidad que ya
existian y no se ejecutaban en ningun sitio.
